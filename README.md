# EnzyWizard-Energy


EnzyWizard-Energy is a command-line tool for calculating molecular energy terms
from a cleaned protein structure and generating a detailed JSON report.
It evaluates the total potential energy and multiple molecular energy terms
using OpenMM. Optionally, it can perform an energy minimization before energy
evaluation, so the reported energy values can reflect either the minimized structure
state or a state closer to the original input conformation.

# example usage:

The examples below use placeholder paths such as `path/to/input.cif` and
`path/to/output_dir/`; replace them with your own cleaned input structure file
and output directory.

Calculate energy terms from a cleaned CIF file with default settings. Energy
minimization is enabled by default with 100 maximum iterations.

```
enzywizard-energy -i path/to/input.cif -o path/to/output_dir/
```

Calculate energy terms from a cleaned PDB file with default settings.

```
enzywizard-energy -i path/to/input.pdb -o path/to/output_dir/
```

Calculate energy terms without energy minimization. This is faster and reports
energies closer to the instantaneous input conformation, but unresolved clashes
or strained coordinates in the input structure can lead to higher or less stable
energy values.

```
enzywizard-energy -i path/to/input.cif -o path/to/output_dir/ --no_minimize_energy
```

Use fewer minimization iterations than the default for a faster run. This can
leave the structure closer to the starting conformation and may give less
relaxed energy values.

```
enzywizard-energy -i path/to/input.cif -o path/to/output_dir/ --minimization_iteration 20
```

Use more minimization iterations for a more relaxed minimized structure. This can
improve convergence for strained inputs, but it increases runtime.

```
enzywizard-energy -i path/to/input.cif -o path/to/output_dir/ --minimization_iteration 5000
```

Run the same cleaned structure with minimized and non-minimized settings and save
the reports into separate output directories. Comparing the reports is useful for
checking how much the reported energy terms depend on local minimization.

```
enzywizard-energy -i path/to/input.cif -o path/to/output_minimized/ --minimization_iteration 100
enzywizard-energy -i path/to/input.cif -o path/to/output_no_minimize/ --no_minimize_energy
```



# input parameters:

-i, --input_path
Required.
Path to the input cleaned protein structure file.
Supported file extensions: .cif, .pdb.

-o, --output_dir
Required.
Path to the output directory for saving the JSON report.
The output directory is created automatically if it does not exist.

--no_minimize_energy
Optional.
Disable performing an energy minimization before energy evaluation.
By default, energy minimization is enabled.

--minimization_iteration
Optional.
Maximum number of iterations for energy minimization.
This option is only used when energy minimization is enabled.
Default: 100.
Must be a positive integer.
A smaller value usually runs faster and may result in energy values closer to the
instantaneous (non-minimized) structure state. A larger value can allow more
minimization steps and may produce more relaxed energy values, but it can
increase runtime.


# output files:

The program outputs the following files into the output directory:

`{name}` is derived from the input file name without its extension.

1. A JSON report
   - energy_report_{name}.json
     - JSON report containing molecular mechanics energy terms.

2. A log file
   - log.txt
     - Processing log containing informational messages and errors.


# output report schema:

The JSON report contains the following fields:

- "report_type"
  - Data type: string
  - Expected value: "enzywizard_energy"
  - Description: The field 'report_type' indicates the type of report ('report': http://purl.obolibrary.org/obo/IAO_0000088) generated by the EnzyWizard-Energy software.

- "energy_terms"
  - Data type: object
  - Description: The field 'energy_terms' indicates molecular energy terms ('molecular': https://goldbook.iupac.org/terms/view/M03989; 'energy': http://purl.obolibrary.org/obo/PATO_0001021) calculated from the protein structure ('protein structure': http://edamontology.org/data_1537) using OpenMM force objects ('OpenMM Force': https://docs.openmm.org/latest/api-python/generated/openmm.openmm.Force.html).

  The "energy_terms" object contains:

  - "total_potential_energy"
    - Data type: number
    - Description: The field 'total_potential_energy' indicates the total potential energy ('potential energy': https://goldbook.iupac.org/terms/view/P04778) calculated from the protein structure ('protein structure': http://edamontology.org/data_1537). # Process:

This command processes the input cleaned protein structure as follows:

1. Load the input structure
   - Read the cleaned CIF or PDB file using Biopython (Bio.PDB).
   - Load the same structure into OpenMM format for force-field-based
     energy evaluation.
   - Resolve the protein name from the input filename.

2. Validate basic input conditions
   - Check that the input file exists.
   - Validate that the input structure satisfies the cleaned-structure requirement.

3. Build the OpenMM system
   - Load the specified OpenMM force field.
   - Construct an OpenMM Modeller object from the cleaned structure.
   - Create an OpenMM system using the protein topology and coordinates.
   - Assign force groups to individual force terms.

4. Initialize the OpenMM context
   - Create the OpenMM integrator and CPU platform context.
   - Set the cleaned protein coordinates into the context.

5. Optionally perform energy minimization
   - If minimization is enabled, run OpenMM local energy minimization
     before evaluating the energy terms.
   - The maximum number of minimization iterations is controlled by
     the user-defined parameter.

6. Calculate energy terms
   - Evaluate the total potential energy of the structure.
   - Evaluate individual molecular energy terms by querying each
     assigned OpenMM force group separately.

7. Save outputs
   - Generate and save a JSON report containing the calculated
     energy terms.


# common errors and solutions:

- "Invalid minimization_iteration"
  - Cause: The value passed to `--minimization_iteration` is zero or negative.
  - Solution: Use a positive integer, such as `20`, `100`, or `5000`.

- "Input not found"
  - Cause: The path passed to `-i` or `--input_path` does not exist or is not a file.
  - Solution: Check the input file path and make sure it points to an existing cleaned CIF or PDB file.

- "Filename too long"
  - Cause: The input file name without extension is longer than the supported filename limit.
  - Solution: Rename the input file to a shorter name and run the command again.

- "Unsupported format"
  - Cause: The input file extension is not `.cif` or `.pdb`.
  - Solution: Use a supported cleaned structure file format.

- "Exception in loading structure"
  - Cause: Biopython could not parse the input file as a usable structure.
  - Solution: Check that the file is valid, non-empty, non-corrupted, and matches its extension.

- "Exception in loading OpenMM structure"
  - Cause: OpenMM could not parse the input file for force-field-based energy calculation.
  - Solution: Check that the cleaned structure file is valid and can be read by OpenMM.

- "Structure must contain exactly one model. Please run 'enzywizard clean' first."
  - Cause: The input structure contains multiple models or no usable model.
  - Solution: Run the structure through `enzywizard-clean` first and use the cleaned output file.

- "Structure must contain exactly one chain. Please run 'enzywizard clean' first."
  - Cause: The input structure contains multiple chains or no usable chain.
  - Solution: Run the structure through `enzywizard-clean` first so it is converted to a single cleaned chain.

- "Cleaned structure must use chain ID 'A'. Please run 'enzywizard clean' first."
  - Cause: The input file is not in the cleaned single-chain format expected by EnzyWizard-Energy.
  - Solution: Use a cleaned output file generated by `enzywizard-clean`.

- "Failed to load OpenMM force field"
  - Cause: OpenMM could not load the force field used for energy calculation.
  - Solution: Check the OpenMM installation and force-field availability in the running environment.

- "Failed to create OpenMM system"
  - Cause: OpenMM could not build a molecular system from the cleaned topology and coordinates, often because the structure contains residues, atoms, or connectivity that the force field cannot parameterize.
  - Solution: Run `enzywizard-clean` again, check the cleaned structure, and review the detailed OpenMM error in `log.txt`.

- "Failed during energy minimization"
  - Cause: OpenMM failed while relaxing the structure, often because of severe clashes, invalid coordinates, or force-field parameterization problems.
  - Solution: Check the cleaned input structure and try running without minimization using `--no_minimize_energy` to isolate whether the failure happens during minimization.

- "Failed to calculate total potential energy" or "Failed to calculate energy term"
  - Cause: OpenMM failed while evaluating the total energy or an individual force-group energy term.
  - Solution: Review the detailed OpenMM error in `log.txt` and check that the cleaned structure can be parameterized by the force field.

- "Failed to write report JSON to"
  - Cause: The report could not be written to the output directory because of a filesystem, permission, or path problem.
  - Solution: Check that the `-o` output directory path is writable and that there is enough disk space.

- Cleaned structure validation failed
  - Cause: The input is not a cleaned single-chain protein structure, or it still contains heterogens, insertion codes, non-standard residues, missing atoms, unexpected atoms, invalid occupancies, or non-continuous numbering.
  - Solution: Review earlier messages in `log.txt`, run `enzywizard-clean`, and use the cleaned CIF or PDB output.

- Energy calculation failed
  - Cause: Force-field loading, system creation, context initialization, minimization, or energy evaluation failed.
  - Solution: Review the specific OpenMM error above this summary in `log.txt`, then check the cleaned structure and OpenMM environment.

- Failed to generate energy report
  - Cause: The calculated energy terms were unavailable, empty, or could not be converted into the report structure.
  - Solution: Review earlier energy calculation errors in `log.txt` and rerun after fixing the upstream problem.

- Output files are missing
  - Cause: The command failed before writing all outputs, or the output directory is not the directory passed to `-o`.
  - Solution: Check `log.txt`, confirm the `-o` output directory, and rerun after fixing earlier errors.

- Output file names are different from expected
  - Cause: Output names use `{name}`, which is derived from the input file name without its extension.
  - Solution: Check the input file name and look for files named `energy_report_{name}.json` and `log.txt`.
